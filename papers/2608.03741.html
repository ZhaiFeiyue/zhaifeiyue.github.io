1. 相关论文 #

本篇 [2608.03741] 是这一 cluster 里唯一站在器件层的工作：它不改调度、不改缓存、不改 agent 逻辑，而是问"给定 agentic 负载形状，硬件目录本身应该长什么样"。八个 peer 按它们与这个问题的接触面分成三层。

同层——为 agentic 负载重排资源的服务系统（最紧密，三篇）：

  • Autellix (2502.13965) —— 把 OS 的 Least Attained Service 提升到 program 级别，用 PLAS/ATLAS 消除 program-level HoL blocking，同延迟下 4–15× 吞吐 [2502.13965]。它与本篇攻击的是同一个物理现象（agentic program 把长短请求混在一个引擎里互相干扰），但 Autellix 的手术刀是时间维（谁先跑），本篇的手术刀是空间维（谁跑在什么器件上）。二者在同一张 roofline 上互不可见：Autellix 的收益全部落在 wait time [2502.13965]，而本篇的模拟器明确不建模排队 [2608.03741]。
  • Halo (2509.02121) —— 把一批同模板 agentic workflow 合并成 consolidated DAG，用 makespan 最小化的 beam-search worker placement 求解，批量最高 18.6×、在线 4.7× [2509.02121]。这是全部 peer 中结构上最接近本篇的一篇：都把"算子/阶段 → 器件"的分配当作一个带成本模型的搜索问题，都用剪枝启发式绕开组合爆炸 [2509.02121]。差别在于 Halo 在给定的同构 GPU 集合上放置 operator，本篇在可自由定型的器件目录上放置 stage —— 而本篇的核心结论恰恰是：当器件目录同构时（GPU），四路拆分基本无利可图 [2608.03741]。
  • KVCOMM (2510.12872) —— 训练无关的跨上下文 KV 复用，RoPE 去/重旋转对齐 + anchor 池偏移近似，多 agent TTFT 最高 ~7.8× [2510.12872]。它是本篇最危险的 peer：本篇的全部收益来自 prefill 重、$I/O\ge10$；KVCOMM 的全部收益来自把重复 prefill 削掉 [2510.12872]。两者在同一个自变量上反向拉扯（详见 §2、§3）。

邻层——用"分配"换成本的另一种范式（一篇）：

  • RouteLLM (2406.18665) —— 用 Chatbot Arena 偏好数据训练 query→强/弱模型路由器，单阈值 $\alpha$ 作为成本-质量旋钮，>2× 成本节省、95% GPT-4 质量 [2406.18665]。它与本篇共享同一个抽象骨架：先给请求/阶段打一个分数，再按预算阈值分派到不同能力档的资源。本篇的 $\sigma(\mathrm{hw})$ 容量分数与按功耗预算剪枝 [2608.03741] 在形式上就是 RouteLLM 的 $P_\theta(\mathrm{win}_s\mid q)$ 与 $\alpha$ 的硬件版本。RouteLLM 沿模型能力轴分配，本篇沿器件规格与位宽轴分配。

下游/上游——决定 $I/O$ 比的那一层（四篇）：

  • AutoGen (2308.08155) —— 多 agent 对话框架，控制流由 auto-reply 循环隐式涌现，六个异构应用共用一套原语 [2308.08155]。它是本篇痛点的生产者：每个 agent 维护自己的对话历史、消息在 agent 间广播 [2308.08155]，这正是"每轮把上下文重新塞回 prompt"的机制来源。
  • Reflexion (2303.11366) —— 把稀疏 reward 放大成 verbal self-reflection 存入 episodic memory，跨 trial 迭代改进 [2303.11366]。它给出了一个反向证据：memory 被刻意限制在 $\Omega\in[1,3]$ 条反思、老的直接丢弃 [2303.11366] —— 即"agent 上下文必然单调膨胀"并非普遍规律，而是设计选择。
  • SWE-bench (2310.06770) —— 2294 个真实 GitHub issue→PR 任务，平均 3010 个非测试文件 / 438K 行的仓库，oracle 检索下 SOTA 仅 4.8% [2310.06770]。它同时提供本篇 $I/O$ 假设的最强支持（真实 coding agent 的上下文确实以万 token 计）与最强反例（把 oracle context 收窄到 ±15 行反而把 Claude 2 从 4.8% 推到 5.9% [2310.06770] —— 上下文长度是可压缩的自变量，不是给定的）。
  • Agent Interoperability Survey (2505.02279) —— MCP/ACP/A2A/ANP 四协议对比，结论是协议互补而非竞争 [2505.02279]。与本篇技术重叠最小，但提供了一个本篇未建模的量：协议层的 agent 间消息（A2A Task/Artifact、ACP MIME multipart [2505.02279]）在物理上就是本篇 N2N 带宽域上的流量，而本篇只把 KV cache 与激活算进 N2N [2608.03741]。

2. 本篇 vs 相关论文的 delta #

2.1 真正新的三件事 #

其一 —— 把"该不该解耦"从架构信仰变成带穿越点的条件命题。 peer 里凡是做解耦/放置的（Halo 的 worker placement [2509.02121]、Autellix 的 program 优先级 [2502.13965]）都默认自己的机制永远有正收益，实验只回答"收益多大"。本篇是这批论文里唯一给出"什么时候收益为负"的：$I/O=1$ 时 PDAF 只有 $0.48\times$ ND、八个模型无一越线 [2608.03741]。这个否定结果比它的肯定结果更稀缺。

其二 —— 结论被证明是器件目录的属性而非算法的属性。 同一模拟器、同一负载、同一模型集合，换 NPU 目录与 GPU 目录得到相反排名：NPU 上 $I/O=100$ 时 PDAF 6/8 最优，GPU 上同一点 PD 在 6/8 模型上追平或胜过 PDAF [2608.03741]。机制在 Table V 里可见 —— GPU 的 32 个阶段分配中 31 个是同一款 H100 [2608.03741]。所有 peer 的结论都锚在具体硬件上（Autellix 在 A100-80GB [2502.13965]、Halo 在 2×H100 NVL [2509.02121]），但没有一篇做过"换硬件目录会不会翻转结论"的对照。这是本篇方法论上的独有贡献。

其三 —— 精度容忍度是工作负载属性而非模型属性。 降 FFN 阶段位宽重创 GSM8K（78%→15%）而 BFCL 不动；降 attention 阶段则把 BFCL 腰斩（18%→11%）而 GSM8K 不降 [2608.03741]。这个按阶段类别分裂的结论在 peer 中无对应物：KVCOMM 的精度-复用折中是单一标量旋钮 $\gamma$ [2510.12872]，RouteLLM 的质量旋钮 $\alpha$ 也是单一标量 [2406.18665]。

2.2 Incremental 的部分 #

  • PD 解耦本身是继承的（DistServe/Splitwise 谱系），本篇自陈 [2608.03741]。
  • 两阶段搜索（解析分数剪枝 → top-$K$ 端到端模拟）[2608.03741] 与 Halo 的"admissible 剩余下界 + beam 剪枝"[2509.02121] 是同一套 A\*-flavored 配方。差别是 Halo 至少测了 placement optimality（1.00 vs 启发式的 0.20–0.40 [2509.02121]），本篇对自己贪心启发式与全局最优的差距一个字都没说，$K$ 的取值也未给出 [2608.03741]。
  • "roofline 决定阶段该配什么硬件"是教科书内容，本篇自己也这么说 [2608.03741]。

2.3 矛盾点（三处，均需标注根源） #

矛盾 A —— prefill 重是前提还是待消除的浪费？

本篇把"agentic 每轮对不断变长的上下文重新 prefill"当作给定的负载形状，并据此论证 $I/O\ge10$ 因而 PDAF 成立 [2608.03741]。KVCOMM 的整个立论则是：多 agent 通信中的重复 prefill 是可消除的冗余，跨上下文 KV 复用能把后续 agent 的 TTFT 压缩到约 1/6–1/7.8 [2510.12872]（见 [2510.12872] 的逐 agent TTFT 分解）。Halo 独立给出同方向证据：consolidated DAG + 共享 prefix cache 后，关闭 cache reuse 会让延迟劣化 51% [2509.02121]。

矛盾根源：本篇的 roofline 里，prefill FLOP 是由输入长度解析导出的，没有任何 prefix-cache 项 [2608.03741]；而 KVCOMM/Halo 测的是有复用层之后的实际 prefill 量。两者不是对同一个量给出不同数值，而是对不同的量各自正确。真正的后果是：在部署了 prefix cache 或 KV 复用的栈上，有效 $I/O$ 会显著低于名义 $I/O$，而本篇自己的曲线在 $I/O=1\to10$ 这一个十倍程内从 $0.48\times$ 摆到 $2.10\times$ [2608.03741] —— 一个复用层就足以把系统从穿越点右边推到左边。本篇未讨论这一点。

矛盾 B —— 端到端延迟由什么主导？

本篇的唯一决策量是模拟 tok/s，模型自陈不含排队、kernel launch、occupancy [2608.03741]。Autellix 的 Fig. 5/6 则直接测出：中等负载下 program 的等待时间已超过执行时间数倍，且 MLFQ 在 program 级别退化到 ≈ FCFS 甚至更差 [2502.13965]。

矛盾根源：metric 层级不同 —— 本篇量的是稳态器件吞吐（供给侧），Autellix 量的是 program 端到端延迟（需求侧）。二者不冲突，但推论会冲突：如果 wait 占端到端的一半以上，那么把器件吞吐做到 $1.92\times$ 在用户可见延迟上远达不到 $1.92\times$。本篇固定 125 req/s、模拟 500 请求 [2608.03741]，唯一显式建模的排队点是 decode 侧受 KV 容量约束的 FIFO 准入 [2608.03741] —— 这恰好是 Autellix 证明最不够用的那种调度策略。

矛盾 C —— 上下文长度是自变量还是因变量？

本篇引 OSWorld 平均 38K / 峰值 100K token 作为 $I/O$ 假设的依据 [2608.03741]。SWE-bench 给出反向证据：把 oracle 上下文压缩到编辑行 ±15 行，Claude 2 的 resolve rate 从 4.8% 升到 5.9%、GPT-4 从 1.3% 升到 3.4%，而扩大 BM25 上下文到 50k 反而把 Claude 2 从 1.96% 拉到 1.22% [2310.06770]。Reflexion 则用 $\Omega\in[1,3]$ 的滑窗记忆达成 SOTA [2303.11366]。

矛盾根源：优化目标不同 —— 本篇观测的是当下部署（把能塞的都塞进 prompt）的经验分布，SWE-bench/Reflexion 观测的是任务成功率对上下文长度的响应，而后者是下降的。也就是说，本篇赖以成立的长上下文，同时是 agent 质量研究正在努力消除的东西。若上下文工程按 SWE-bench 的方向演进，$I/O$ 会朝穿越点左侧移动。

3. 可攻击面 #

攻击 1（最致命）—— 论文实测过的两个真实工作负载都落在它自己的穿越点以下。 Table VII 报告 BFCL 平均 11,174 prefill / 1,472 decode token，GSM8K 995 / 313 [2608.03741]。换算成本文自己的 $I/O$ 定义分别约 7.6 与 3.2 —— 前者略低于穿越点 10，后者深在 $I/O=1$（$0.48\times$）与 $I/O=10$（$2.10\times$）之间那段最陡的下坡上 [2608.03741]。也就是说，全文唯二有真实模型跑过的负载，按本文自己的曲线读，PDAF 都不该赢。支撑 $I/O\ge10$ 的只有引用的 OSWorld 统计，而 OSWorld 既不在八模型吞吐集合也不在量化集合里。论文没有把这两个数放在同一张图上对照。

攻击 2 —— 穿越点的陡峭度使整个结论对负载估计误差极不鲁棒。 4.4 倍的收益摆幅压缩在一个十倍程内 [2608.03741]。任何真实部署的 $I/O$ 都不是一个标量：AutoGen 的六个应用从两 agent 往返到 GroupChatManager 动态群聊，形状差异极大 [2308.08155]；Autellix 明确指出 agentic 负载的 decode steps 与 calls-per-program 都是重尾分布 [2502.13965]。在重尾分布下用分布中心去读一条在中心附近有 4.4 倍摆幅的曲线，是本篇方法论上最脆的一环。正确做法应是对 $I/O$ 的分布取期望收益，而非对期望 $I/O$ 取收益 —— 由于曲线在穿越点附近强烈非线性，这两者不相等。

攻击 3 —— 模拟器的误差结构对 MoE decode-FFN 恰好最不利。 PP 点对点随规模从 $0.82\times$ 收敛到 $1.00\times$，而 EP all-to-all 反向发散到 $1.21\times$，且两个原语共用一套带宽模型（模拟值完全相同）[2608.03741]。本篇八个模型里绝大多数是 MoE，而 DF 阶段正是 EP 流量的所在。误差方向未被讨论。对照 Halo：它同样依赖 profiled 成本模型，但至少给出了 placement optimality 的独立测量 [2509.02121]；本篇没有任何等价的端到端校准 —— Fig. 2 只验证了算子级 TFLOPS [2608.03741]。

攻击 4 —— 量化结论的效应量在自陈噪声之内，且证据基座与吞吐结论无交集。 8-bit 均匀量化在 BFCL 上（21%）高于未量化基线（18%），4/8/8/8 与 8/8/4/8 在 GSM8K 上也高于未量化基线 [2608.03741]；论文自陈量化研究只有一个模型、两个任务、无重复实验。既然基线本身能被"量化"抬高 3 个点，那么所有 BFCL 上 6–7 个点的差值都不可判读。更麻烦的是 Qwen3.5-32B 既不在八模型吞吐集合也不在三模型消融集合中 —— 精度轴与吞吐轴没有共同模型，因此 §V-B 描述的"量化搜索产出 $\mathbf{q}^\star$ 喂给硬件搜索"这条流水线在全文从未被端到端执行过 [2608.03741]。

攻击 5 —— 多处未调和的内部数字。 摘要 75%、§I Fig. 1(b) $1.82\times$、§I 贡献三 $2.06\times$ 三个头条增益并存且后者在 §VI 再未出现；Vera Rubin 的阶段分配在 §I 与 §VI-B 中互为反向；Table II 标题称 2–5 个点、正文称七类技术、表中只列五类 [2608.03741]。对一篇唯一产物是数字的模拟论文，这类不一致直接侵蚀可信度。

攻击 6 —— 没有任何任务成功率指标，而它自己的方法引入了质量风险。 本篇的四路精度自由度会把 BFCL 从 18% 打到 11% [2608.03741]。Autellix 至少明确界定了 scope（serving 层不改变输出质量 [2502.13965]），Halo 明确以 exact-answer 与 perplexity 守住质量（10.01 vs 10.57 [2509.02121]），KVCOMM 用回退 dense prefill 兜底 [2510.12872]。本篇提出了会损质量的旋钮，却把质量证据放在一个与吞吐实验不相交的模型上，且没有回退机制。

攻击 7 —— PhaseAutoSwitch 用 $L>1$ 判 prefill 相，与现代 agentic 调度器不兼容。 任何 $L>1$ 的 decode 路径（推测解码、chunked prefill 与 decode 混批、MTP）都会被误判为 prefill 并套用 prefill 精度 [2608.03741]。而 chunked prefill/混批恰恰是 Autellix、Halo 这类 agentic serving 系统赖以工作的机制 [2509.02121]。这不只是实现瑕疵：如果 prefill 与 decode 在时间上不可分，"按相位分配硬件"这个前提本身就要被重新论证。

4. 生态位 #

范式定位：从"给定硬件优化软件"翻转为"给定负载定型硬件"。 这个 cluster 的软件侧三篇 —— Autellix 调度、Halo 放置、KVCOMM 复用 —— 共享一个隐含前提：硬件是外生给定的（A100-80GB、2×H100 NVL）[2502.13965][2509.02121]。本篇把这个前提变成决策变量，并给出了一个软件侧看不见的结论：在同构商用目录上，attention/FFN 拆分没有东西可分，因为搜索给 32 个阶段中的 31 个选了同一款卡 [2608.03741]。这为软件侧三篇提供了一个边界说明 —— 它们之所以只能在时间维和缓存维找收益，部分是因为空间维在商用目录上已经退化。

这不是 paradigm shift，而是 paradigm 的成立条件研究。 PDAF 没有提出新机制（PD 已有、AF 是自然推论），它提出的是判据。这类工作的学术生态位类似 RouteLLM 之于模型路由：路由本身不新，RouteLLM 的价值在于把它变成可用偏好数据学习、可用单阈值控制、并证明能跨模型对迁移的东西 [2406.18665]。本篇的对应物是把"何时该拆"还原成 DA 与 DF 两个 roofline 位置之间的间隙宽度，并证明三类外生变量（负载形状、器件目录自由度、模型架构参数）各自独立地开合这个间隙 [2608.03741]。

采纳证据：这个 cluster 里最弱的一档。 本篇代码未公开，只承诺 acceptance 后开源 [2608.03741]，且依赖三个外部组件（MASE 量化 pass、PLENA NPU 基底、MemExplorer 功耗模型）才能复现。对照：

它是这张表里唯一既无代码又无端到端真机结果的一篇。这不必然否定结论 —— 一个尚不存在的 NPU 目录本来就只能靠模拟 —— 但它意味着本篇的正确定位是设计空间探索报告，而非可直接指导采购的结论。把 §VI 的 $\times$ND 数字当作硬件选型依据是误用。

与协议层的关系。 2505.02279 描述的 A2A/ACP/MCP 消息在物理上是跨节点流量 [2505.02279]，而本篇的 N2N 域只装了 KV cache 与激活 [2608.03741]，D2D 与 N2N 在其假设下相差 72 倍。多 agent 部署下协议层流量落在哪个域、是否与 KV 传输争带宽，是本篇模型的一个结构性空白。

5. 未探索方向 #

方向 1 —— 有效 $I/O$：把 KV 复用折扣接进 roofline，重算穿越点。 Halo 的成本模型已经有现成的复用折扣系数 $\gamma_v$（KV）、$\sigma_v$（权重）、$\lambda_v$（检索），且是离线 profile 得到的 [2509.02121]；KVCOMM 给出了这些折扣在多 agent 下的实测复用率与精度代价 [2510.12872]。把 $\gamma$ 乘进本篇 prefill 阶段的 $\Phi$ 与 $\beta$，可以直接得到"复用层存在时穿越点移到哪里"。这是本 cluster 里收益最高、技术上最现成的组合，且能一次性化解 §2.3 的矛盾 A。

方向 2 —— 阶段解耦 × program 级调度的联合设计。 Autellix 的 PLAS/ATLAS 目前把整条 program 的累计服务时间映射到单一优先级 [2502.13965]。在 PDAF 拓扑下有四个独立资源池，每个池可以有自己的队列 —— 一个自然的问题是：program 优先级该在四个池里同步（保持 program 语义）还是各自独立（最大化各池利用率）？Autellix 的 ATLAS 已经证明多线程 program 必须用 critical-path max 而非 sum [2502.13965]，PA→PF→DA↔DF 的流水线正是一条固定 critical path，二者可以直接对接。这也顺带补上本篇 $I/O=1000$ 时收益回落到 $1.27\times$（decode 硬件闲置 [2608.03741]）的调度侧解法：闲置的 decode 池可以被跨 program over-commit。

方向 3 —— 按请求路由精度画像。 本篇证明了精度容忍度是工作负载属性：BFCL 类（长上下文、工具调用）不能降 attention 位宽，GSM8K 类（短上下文、算术推理）不能降 FFN 位宽 [2608.03741]。RouteLLM 已经证明从 query 文本就能预测它的难度类别，且路由器能跨模型对迁移、开销 <0.4% [2406.18665]。把 RouteLLM 的分类器输出从"强/弱模型"换成"四阶段精度画像 $\mathbf{q}$"，就得到一个 per-request 的精度路由器 —— 这正好绕开本篇"单一全局精度必牺牲其一"的困境 [2608.03741]，而本篇把 $\mathbf{q}$ 当作部署期常量。

方向 4 —— 用真实 agent trace 的 $I/O$ 分布替代标量扫描。 SWE-bench 提供 2294 个真实仓库任务及其上下文统计 [2310.06770]，AutoGen 六应用提供多 agent 拓扑下的调用模式 [2308.08155]。用它们导出 $I/O$ 的经验分布，再对本篇的收益曲线求期望，可以直接检验 §3 攻击 2。由于曲线在穿越点强非线性，期望收益很可能显著低于按均值 $I/O$ 读出的值 —— 这是一个能被现有数据立即证伪或证实的定量预测。

方向 5 —— 上下文压缩与硬件解耦的对抗性联合优化。 SWE-bench 的收窄上下文提升成功率 [2310.06770] 与 Reflexion 的 $\Omega\le3$ 滑窗 [2303.11366] 指向同一个趋势：agent 质量研究在压缩上下文，而本篇的收益依赖上下文膨胀。一个诚实的联合研究应该同时优化 (成功率, tok/s)，而不是各自单目标 —— 目前没有任何一篇做这件事，因为 serving 侧论文普遍不测成功率（Autellix 明确不测 [2502.13965]，Halo 用 exact-answer 约束把质量固定 [2509.02121]）。

方向 6 —— 补上论文自己指出却未做的闭式界。 本篇在 §VII 自陈"PDAF 的收益很大程度上可由 decode-attention 算术强度与激活 FFN 计算量预测"，却把它留作未来工作 [2608.03741]。给定 DA 与 DF 的算术强度比与功耗预算，PDAF 相对 PD 的收益上界应当是可闭式写出的。有了这个界，Table V 那种"扫 8 模型 × 9 比值 × 4 模式"的暴力扫描可以被替换成一次代数判据 —— 对本篇最强的解释性结论而言，这是从 correlation 走向 mechanism 的关键一步。

方向 7 —— 把协议层流量纳入 N2N 预算。 MCP/A2A/ACP 的消息、Agent Card 发现、SSE 流式推送都占用与 KV 传输相同的网络域 [2505.02279]。在四路解耦下 N2N 已承载跨边界 KV 与激活 [2608.03741]，多 agent 部署时协议流量是否成为第二瓶颈，是一个没人建模过的量。
