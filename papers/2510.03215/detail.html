Cache-to-Cache: Direct Semantic Communication Between Large Language Models — L2 #

1. TL;DR #

两个 LLM 不再用文本对话，而是让 Sharer 的 KV-Cache 经神经网络投影后、以残差 + 逐层门控的方式融进 Receiver 的 KV-Cache。冻结双模型只训融合器：比单模型高 6.4–14.2%、比文本通信高 3.1–5.4%，且平均 2.5× 加速（省掉逐 token 解码）。

2. Q1 / Q2 / Q3 #

Q1 · 痛点（为什么文本通信不够） #

多 LLM 协作当前全部走 text-to-text (T2T) 接口：模型把高维内部表示压成 token 串，接收方再解压。三个固有缺陷：

  1. 信息瓶颈：文本是低带宽介质，高维语义被压成线性字符串后不可逆地丢失（例：把

    作为"段落分隔符"的结构语义无法用一句话可靠传达）。

  2. 歧义：自然语言天生歧义，即便 MCP / A2A 协议也不足以支撑开放域灵活协作。
  3. 延迟：每一次交换都要串行逐 token 解码；Sharer 解码 80 个 token 就要 ~1.3s（Table 3）。

    作为段落分隔的结构语义，Writer 放错内容；C2C 把 Coder 的 KV-Cache 直接投影进 Writer，同时传递"语义理解"与"精确插入位置"。这张图把抽象的"信息瓶颈"落到一个可感知的失败案例上。

    Q2 · 方法（C2C 做了什么） #

    把 KV-Cache 本身当作通信介质。Sharer 与 Receiver 各自 prefill 同一上下文，产生各自的 KV-Cache；一个 Cache Fuser 把 Sharer 的 cache 投影到 Receiver 空间并与之融合，以残差方式加回 Receiver 的 cache；Receiver 用融合后的 cache 解码回复。整个通信是全并行的一次投影，不需要串行解码。

    核心技术壁垒：跨模型族、跨尺寸、跨 tokenizer 地把一个模型的 KV-Cache 注入另一个模型而不破坏后者原有语义——关键不在"投影"而在"残差融合 + 逐层可学习门控"。消融显示：直接用投影后的 Sharer cache 替换 Receiver cache（无残差）准确率坍塌到 ~20%（低于 4 选 1 随机的 25%）；加上残差立刻 +24.18%（Table 8）。这条"永远加修正、绝不覆盖"的约束，加上 Gumbel-sigmoid 门控在训练末期退火成二值开关逐层决定是否注入，是最难复制、也最 load-bearing 的设计。详见 §7。

    Q3 · 结果 #

    • 比单模型平均高 +9.6 ~ +11.9%（三种 Sharer，Table 4）。
    • 比 T2T 平均高 +3.1 ~ +5.4%，且 2.5× 平均加速（最高 14.4×，当 Sharer 是只会生成冗长文本的 base 模型时）。
    • 惊人案例：Qwen3-4B-Base 单独几乎 0% 准确率（不会 follow instruction），作为 Sharer 却能把 Receiver 抬到 43.95% —— C2C 能榨取"自己没用"的模型的知识。
    • 训练极廉价：~300 步 / <9 GPU·小时 即达到接近最终 checkpoint 的精度（Table 12）。

    4. 作者证明 #

    无形式化作者证明 — 仅实证。 本文无收敛定理 / 样本复杂度界 / PAC 式保证；全部结论由 oracle 实验与基准测试支撑。但方法由若干 load-bearing 方程定义，下面给出符号表、物理意义与 6 项一致性（量纲 / 边界）检查。若要补"理想中应有的保证"，最缺的是：在何种 Sharer–Receiver 表示相容性假设下，融合后 Receiver 的预测损失不会被劣质 Sharer 抬高（即对 §5 列出的"弱 Sharer 污染强 Receiver"失败模式给出可证明的充分条件）。

    符号表 #

    符号含义
    $X_{[0:n]}$长度为 $n$ 的输入 token 序列
    $c_i,\; d$token $i$ 的 KV 状态；$d$ = 所有层 flatten 后的 KV 维度
    $C(\cdot)\in\mathbb{R}^{n\times d}$prefill 后逐 token 的 KV-Cache
    $\oplus$序列维拼接
    $N,\; n$Receiver 层数；当前层 index
    $G(n)$层映射：Receiver 第 $n$ 层 → Sharer 层 index（terminal 对齐）
    $F_n$第 $n$ 层的 fuser（投影+融合+动态加权+门控）
    $C^S_{G(n)}$Sharer 在映射层的 cache（上标 $S$）
    $\mathcal{C}^F$融合后的上下文 cache，替换 $C(X)$
    $E$oracle 实验中的 few-shot 示例段

    载重方程与物理意义 #

    (1) 融合 cache（残差整合）：

    $$\mathcal{C}^F = \left\{\, C_n(X) + F_n\!\left(C_n(X),\, C^S_{G(n)}(X)\right) \right\}_{n=1}^{N}$$

    物理意义：融合 cache = Receiver 自身 cache 加 fuser 产生的修正项；残差保证原 cache 不被破坏性覆盖。

    (2) 融合后解码：

    $$y_{i+1} = P\!\left(y_i \mid \mathcal{C}^F(X) \oplus C(Y_{[0:i]})\right)$$

    物理意义：Receiver 以"含双方语义"的融合 cache 作为上下文解码，生成端 cache 仍是自己的。

    (3) Enrichment oracle 切片：

    $$C^*(X) = C_{[|E|:|E|+|X|]}(E \oplus X)$$

    物理意义：对 $E\oplus X$ 做 prefill，但丢弃 exemplar 段，只保留 question 对齐的 KV 切片——问题 token 在 prefill 时已被 exemplar 语义"浸染"，却不增加解码时可见的 cache 长度，从而把"语义富化"与"看更多 token"解耦。

    (4) 训练损失（SFT 式 next-token，仅更新 fuser）：

    $$\mathcal{L} = -\sum_i \log P\!\left(y_i \mid \mathcal{C}^F(X) \oplus C(Y_{[0:i]})\right)$$

    6 项一致性检查 #

    1. 量纲/残差相容：$F_n$ 的输出必须与 $C_n(X)\in\mathbb{R}^{n\times d}$ 同形才能相加 → 投影模块把 Sharer cache 映回 Receiver 维度，检查通过。
    2. $G(n)$ 良定义：terminal 对齐从输出侧配对（末层↔末层、次末↔次末…直到浅模型首层），$G$ 在 $[1,N]$ 上唯一定义到较浅模型深度；无越界。
    3. 初始化退化为基线：若 $F_n\approx 0$，则 $\mathcal{C}^F = C_n(X)$，即退化成 Receiver-only —— 一个 sane 下界。与 Table 6 "Identical ≥ Single" 及门控行为一致。
    4. 门控边界：Gumbel-sigmoid 输出 $\in(0,1)$；温度 $\tau:1.0\to0.001$ 时趋于二值 $\{0,1\}$，极限行为正确（训练可微、推理硬开关）。
    5. oracle 切片长度：$|C^*(X)| = |X|$，与 Direct 的 cache 长度相同 → 确实隔离了"富化"与"长度"。与 Table 1 "Cache Len. = |X|" 行自洽。
    6. 解码开销：$\mathcal{C}^F(X)$ 与 $C(X)$ 同为 $n\times d$，注意力覆盖的 KV 位置数不变 → 解码 FLOPs 不增，只多一次性 90ms 融合。与 Table 3（C2C prefill = 20+90ms，decode 与 Receiver 同量级）自洽。

      7. 实现 cross-reference #

      • 官方代码：https://github.com/thu-nics/C2C （论文 §0 公布）。
      • Cache Transformation Oracle 的可复现核心（§A.3.2，L1 已抓取代码片段）：投影器对 Sharer 的 past_key_values[-1] 的 K、V 分别做 k_projector / v_projector，再对 torch.dstack([project_k, project_v]) 与 target 的同构张量算 MSE。这是验证"cache 可转换"的最小实现，与正式 fuser 的区别是它用 MSE 对齐表示而非 next-token 损失。

      核心技术壁垒（最难复制的一点） #

      残差约束 + 退火二值门控下的跨架构 cache 注入。 复制者最容易踩的坑是"既然要传 Sharer 的语义，就用 Sharer 的 cache 替换 Receiver 对应层"——Table 8 的 Project 行证明这会把精度打到随机以下（~20%）。正确做法有三层硬约束缺一不可：(1) 永远残差，融合输出是加到 Receiver cache 上的修正项，初始化近 0 时安全退化为 Receiver-only；(2) 逐层 Gumbel-sigmoid 门控，训练用温度 1.0→0.001 退火把软门变成推理期硬开关，让模型自己学"哪些层该注入"（由 §3.2.1 发现的层异质性驱动——28 层里可能只有少数几层真正受益）；(3) 门控之外还有 input-aware 动态加权，在通用训练下门几乎全开（>98.21%）、由动态权重承担调制，在任务特定训练下门变稀疏（52.67%）——两种 regime 的存在说明单靠门控不够。谁省掉其中任何一层，跨模型融合都会退化或坍塌。

      关键实现细节（易漏的 1–2 个 trick） #

      1. Token 对齐的"最大覆盖"选择（§3.3.3 / A.1.2）：跨 tokenizer 时，把 Receiver 每个 token 解码成字符串再用 Sharer tokenizer 重编码；遇到一对多，选字符串覆盖最长的 Sharer token（而非 first-occurrence）以保留最多表面语义。模板段则用 补齐长度、不做语义对齐。>80% 序列两种策略结果相同，但差异那部分影响质量。
      2. Terminal（末端）层对齐（§3.3.3 / A.1.1）：从输出侧往回配对（末层↔末层…），优先对齐承载高层语义的深层，而非 depth-normalized 均匀映射；论文选它因为"更简单、更直接、实证略好"。复现时若默认写成按比例映射，会偏离论文配置。
