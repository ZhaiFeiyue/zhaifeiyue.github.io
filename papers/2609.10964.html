Mode A per-paper synthesis. Target vs 8 related algorithm-category peers. Note on cluster shape: the assigned peers are a category-level neighborhood (all category: algorithm), not a topic-level one. Only a subset touch this paper's actual problem (agent workflows, LLM serving, tail-risk / search). The synthesis below is honest about which peers are true methodological kin and which are only category-mates useful as contrastive references.

1. 相关论文 (which peers, and why) #

Sorted by methodological proximity to the target (tail-risk-aware pre-engine turn-release scheduling).

Tier 1 — direct problem-space kin (agent workflows / serving substrate / test-time compute governance):

  • 2110.14168 (Training Verifiers / GSM8K) — the closest conceptual relative. It governs test-time compute for multi-step reasoning: sample many candidates, then a learned scorer decides which to trust. The target governs test-time serving compute: many ready turns, then a tail-risk score decides which to release. Both papers are fundamentally "score-and-select under a compute budget," and both flag a search-monotonicity limit (verifier: accuracy peaks ~400 samples then falls [2110.14168]; target: speedup is non-monotonic in arrival rate). See §2, §5.
  • 2407.21783 (Llama 3 Herd) — supplies the serving primitives the target's engine layer rests on and shares the "decouple two knobs" pattern. Llama 3's rejection sampling explicitly uses PagedAttention/vLLM for >2× throughput [2407.21783]; the target evaluates on vLLM 0.20.2 unmodified [2609.10964]. Both also share the "which × whether" decomposition flavor: Llama 3 separates compute-budget (scaling law) from allocation (data mix); the target separates release-order ($U_v$) from release-budget ($B_m$).
  • 2005.11401 (RAG) / 2401.18059 (RAPTOR) — both are retrieval-under-budget algorithms whose core move is truncation to top-$K$ / a token budget, structurally analogous to the target's committed-work budget $B_m$. RAG's top-$K$ marginalization discards ranked-below-$K$ mass [2005.11401]; RAPTOR's collapsed tree "greedily fills a 2000-token budget" [2401.18059]. The target's feasibility set $\mathcal{F}(t)=\{v:W(t)+\widehat w_v\le B_m\}$ is the same greedy-fill-under-budget skeleton, but the budget is adaptive to congestion rather than a fixed constant.

Tier 2 — methodological-technique kin (shared math machinery, different domain):

  • 2301.04104 (DreamerV3) — shares the online quantile / percentile-normalization machinery. Dreamer normalizes returns by the 5–95 percentile range with a max(1,S) denominator floor to keep a fixed entropy coefficient valid across reward scales [2301.04104]. The target runs an online $\alpha=0.95$-quantile SGD ($\widehat\tau_n$, Eq. 9) and a max{1,·} floor on the work estimate $\widehat w_v$ (Eq. 10) — the same "robust scale-invariant statistic + protective floor" design idiom, applied to flow-time tails instead of returns.

Tier 3 — category-mates only (contrastive, not methodological kin):

  • 1706.03762 (Transformer) — the architectural substrate every agent turn runs on, but a compute-graph paper with no scheduling/tail-risk content. Useful only as the "workload primitive" reference: each LLM turn the target schedules is a Transformer forward pass whose prompt/decode asymmetry (§Table 1: 7,160/97 prompt/completion) drives the target's $\gamma=4$ decode weighting.
  • 2402.06363 (StruQ) — a security/defense-training paper; shares nothing methodologically with tail-aware scheduling. Its only cross-link is the shared honesty pattern of a quantified residual gap (StruQ leaves GCG at 58% ASR [2402.06363]; the target leaves a no-formal-guarantee gap and single-seed variance gap). Included here purely as a category-neighborhood contrast.
  • 2410.02367 (SageAttention) — a kernel-quantization paper; orthogonal problem (making one turn's attention cheaper vs deciding when to release turns). Complementary, not competitive: SageAttention would shift the target's whole load–latency curve left by speeding each turn, without changing the release-scheduling insight.

2. 本篇 vs 相关论文的 delta (what's new, incremental, contradictory) #

Genuinely new (no peer does this):

  1. Pre-engine release time $D_v$ as an explicit decision variable. Every serving peer here (vLLM lineage via Llama 3 [2407.21783]) treats readiness = submission. The target's contribution is to insert a controllable gate before the engine and prove (empirically) that idling admissible capacity under congestion is beneficial [2609.10964]. None of the 8 peers models a release-timing variable.
  2. CVaR occupation-form reduction (Eq. 7→8). The reduction of a distribution-level tail-risk objective to a per-workflow instantaneous holding-cost rate that a greedy local scheduler can act on using only age + one online quantile is the paper's hardest-to-replicate insight [2609.10964]. No peer here uses CVaR; DreamerV3's percentile normalization [2301.04104] is the nearest analog but is a variance-reduction heuristic, not a tail-risk objective with a variational derivation.

    3. Incremental (a peer already did the core move, target adapts it):

    1. Budget-gated greedy selection is incremental over RAG/RAPTOR's top-$K$/token-budget truncation [2005.11401][2401.18059]. The target's delta is making the budget adaptive (integral congestion controller, Eq. 13–15) rather than a fixed hyperparameter. Notably, the ablation shows this adaptive-budget delta is the smaller contribution (−10.7%/−11.6% over a fixed budget) [2609.10964].
    2. $c\mu$-per-unit-work priority index is a classical queueing rule; the target's incremental step is plugging the tail-risk holding rate into the numerator and a causal token-work estimate into the denominator (Eq. 11).
    3. Score-then-select under a compute budget is shared with the verifier paper [2110.14168], but the target selects what to admit into a shared resource (an online, irrevocable decision) whereas the verifier selects the best of an already-generated batch (an offline, revocable rerank). The target's decision is harder because it is one-way (committed turns cannot be withdrawn [2609.10964]).

      4. Contradictory / tension across the cluster:

      1. The verifier paper finds more search monotonically helps only up to a bound, then adversarial over-optimization degrades it [2110.14168]. The target finds an analogous non-monotonicity in arrival-rate speedup but attributes it to tail-set churn (P95 over only 100 workflows), not over-optimization [2609.10964]. Same surface symptom (non-monotone benefit of "more"), different root cause — worth flagging so a reader does not conflate them.

        2. 3. 可攻击面 (adversarial rebuttal against specific claims) #

        1. "Up to 3.5× P95 speedup" rests on single-seed points. Each Fig. 2 point is one paired run with one arrival seed, and P95 over 100 workflows is dominated by ~5 workflows [2609.10964]. Contrast the discipline of peers: Llama 3 reports binomial confidence half-widths $CI(S)=1.96\sqrt{S(1-S)/N}$ and calls them a lower bound [2407.21783]; DreamerV3 runs 5 seeds [2301.04104]. The target's headline tail statistic has no variance reporting, which is the single most attackable methodological choice given the metric is itself a tail quantile.
        2. The paper's own ablation undercuts its title. The title foregrounds tail-aware and budget-adaptive release, but budget adaptation contributes only −10.7%/−11.6% while ordering does −59.5%/−63.5% [2609.10964]. This mirrors DreamerV3's ablation honesty (each trick load-bearing on some subset [2301.04104]) — but here the implication is that a fixed budget + tail-aware ordering would capture ~90% of the gain, questioning whether the adaptive controller (Eqs. 13–15, the paper's most complex machinery) earns its complexity.
        3. No formal guarantee for the closed loop. The $c\mu$/interchange justification holds only for a frozen non-preemptive snapshot; the online quantile SGD and congestion controller are heuristic integral updates with no convergence/stability proof for the coupled $(\widehat\tau,\lambda)$ dynamics [2609.10964]. This is a shared weakness across the whole algorithm cluster — Transformer's $1/\sqrt{d_k}$ is a heuristic [1706.03762], RAG has no $K$-truncation bound [2005.11401], verifiers have no ranking-error bound [2110.14168] — so it is a fair-play omission, not a disqualifier. But unlike those, the target's object is a control loop, where a regret/competitive-ratio bound would be both natural and much more valuable.
        4. $\gamma=4$ vs prompt-dominated traces is unanalyzed. The work estimate up-weights decode tokens 4× yet both traces are ~70–85× prompt-dominated (7,160/97, 8,244/93) [2609.10964]. On these traces $\widehat w_v \approx \widehat p_v$ regardless of $\gamma$, so the paper cannot claim its decode-weighting design is validated — a workload with balanced prefill/decode would be needed. SageAttention's careful per-model profiling of where quantization is safe [2410.02367] is the contrasting standard the target does not meet for its $\gamma$ choice.
          1. Baseline is only Eager Release. No comparison against the application-aware serving baselines the paper itself cites in Related Work (Parrot, Agentix, JITServe). A reviewer can argue the true competitor is Agentix's program-level attained-service prioritization, not naive eager release, so the 3.5× is against a strawman-strength baseline.

            2. 4. 生态位 (paradigm-shift positioning, adoption evidence) #

            • Paradigm layer. The target sits in the workflow-level serving-control layer, one level above the engine schedulers (vLLM/Orca) it runs on top of, and one level below agent frameworks (ReAct/DSPy). Its paradigm claim — "readiness ≠ obligation to submit" — is a genuine reframing: it converts a runtime default (eager release) into an explicit online decision variable. This is a smaller but sharper move than the architectural paradigm shifts in the cluster (Transformer's "attention is all you need" [1706.03762]; RAG's parametric+non-parametric memory [2005.11401]).
            • Adoption evidence: weak. Unlike the well-adopted peers — Transformer (every modern LLM [1706.03762]), RAG (HuggingFace modeling_rag.py [2005.11401]), SageAttention (pip install sageattention, integrated into ComfyUI/Diffusers [2410.02367]) — the target has no released code and no downstream integration [2609.10964]. Its [实现未公开] status plus single-seed evaluation places it at "promising but unvalidated" on the adoption axis.
            • Complementarity, not competition. The target is orthogonal to (and stackable with) most of the cluster: SageAttention speeds each turn, Llama 3 supplies the model + rejection-sampling serving pattern, verifiers govern which outputs to keep. A production agent stack could run all four simultaneously. The target's niche is the one lever none of them touch: when to submit.

            5. 未探索方向 (hybrid / adaptive directions from the cluster) #

            1. Learned release policy à la verifier value function. The target hand-derives $U_v(t)$ from CVaR. The verifier paper shows a learned token-level value function beats hand-scored ranking for multi-step tasks [2110.14168]. Hybrid: train a small value head predicting "expected tail contribution of releasing turn $v$ now," replacing the analytic $h_i/\widehat w_v$ — potentially capturing tool-gap and workflow-state features the age-only holding rate ignores.
            2. Scaling-law-forecast the budget bounds. The target fixes budget $\in[30k,300k]$ by hand [2609.10964]. Llama 3's two-step downstream scaling-law forecasts a compute-optimal setpoint before committing [2407.21783]; an analogous law mapping (model size, GPU count, trace token profile) → $(B_{\min},B_{\max},\lambda_{\max})$ would remove the per-deployment hand-tuning the paper currently requires.
            3. Hierarchical release over a workflow tree. RAPTOR shows multi-abstraction-level selection beats flat top-$K$ [2401.18059]. Agent workflows have latent sub-goal structure; a release policy that scores sub-trees (a workflow's remaining turn-chain) rather than the single ready turn could exploit look-ahead the target's one-ready-turn-per-workflow model discards.
            4. Co-design release gate with a cheaper engine. SageAttention's plug-and-play 2× per-turn speedup [2410.02367] would shift the congestion onset; jointly tuning the release controller to a quantized-attention engine (where effective service rate is higher) is an unexplored two-layer optimization.
            5. Robust scale-invariance transplant from DreamerV3. DreamerV3's max(1,S) percentile normalization stabilizes a fixed hyperparameter across wildly different reward scales [2301.04104]. The target already borrows a max{1,·} floor; a fuller transplant (percentile-range normalization of $\widehat w_v$ and of congestion signals) could let one fixed config span the model/GPU grid without the current per-target budget bounds.
            6. Adversarial-robustness of the release gate. StruQ frames injection as a channel-mixing flaw and hardens against it [2402.06363]. A multi-tenant agent server exposing a release gate invites a dual: a tenant that inflates its $\widehat w_v$ or ages workflows to game the holding rate could starve others. No peer studies scheduling-level adversarial gaming; the target's priority index is an untested attack surface.
